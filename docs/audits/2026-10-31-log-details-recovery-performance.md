# 日志、结果卡与归档体验修复

本轮落实此前确认的 7 项问题。修改位于前端；归档文件结构、串口协议、原始字节和设备所有权契约沿用现有实现。

## 修复结果

| 场景         | 原问题                                                               | 修改后的行为                                                                                                                 |
| ------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 固件操作结果 | 长串口名和输出路径把结果卡撑出最小窗口，日志与恢复按钮不可见         | 详情内部滚动，路径默认省略，可展开和复制原始输出路径；展开后端口使用整行；按钮保持在卡片底部，新结果重置展开与复制反馈       |
| 串口日志导出 | 等待读取或保存对话框时可重复触发，读取／写入失败没有可见反馈         | 第一次异步操作前锁定来源和导出按钮，显示保存中／成功／失败状态，取消或失败后可重试；保留分页总数快照及会话修订检查           |
| 批量归档     | 目录对话框打开期间可重复执行，结果使用后来修改的表单和槽位信息       | 在提交后端时记录执行配置，在完成时记录结果；目录选择前锁定归档；表单编辑不会修改归档；取消、失败、清理后的晚返回均有回归覆盖 |
| 查找与输入法 | 输入法确认中的 Enter／Escape 触发跳转或关闭                          | `isComposing` 或 `keyCode === 229` 时不处理查找按键，普通按键仍可跳转和关闭                                                  |
| ANSI 高亮    | 整行查找计数命中，但跨颜色片段的关键词没有高亮                       | 在完整纯文本上计算命中范围，再按字符位置分配给颜色片段，保留显示文本和样式；范围游标随片段前进                               |
| 应用日志查看 | 256 KiB 尾部日志可以产生上万 DOM 行，搜索还为全部命中行生成高亮 HTML | 每段最多显示 300 行，仅为当前段生成高亮；保留换行、完整匹配数、跨段前后跳转、刷新阅读位置及全文复制                          |
| 实时日志查找 | 相同关键词下，每次追加都重复匹配整个窗口的旧文本                     | 按唯一行 ID 缓存当前关键词的匹配结果，仅新行重做文本匹配；仍按当前窗口顺序生成结果，不假定 ID 数值顺序，缓存沿用现有有界清理 |

归档成功后再次打开目录选择并取消，会保留上一次归档成功状态和路径。归档选择／写入期间，开始、重试与读取操作显示或遵守忙碌状态。已完成槽位和执行配置不会被后续探测、删除槽位或配置编辑改写。Excel 统计等待任务完成后的刷新，仅接受同一张表的有效结果；未完成刷新或刷新失败时记录 `null`，避免混入任务开始前或另一张表的统计。

## 可复现的性能证据

| 场景与指标                                               |  修改前 |  修改后 | 验证方式                                                              |
| -------------------------------------------------------- | ------: | ------: | --------------------------------------------------------------------- |
| 12,000 行应用日志：挂载的日志 DOM 行                     |  12,000 |     300 | 组件及 Chromium 回归；查找仍覆盖全部 12,000 行                        |
| 20,000 行窗口、相同关键词、20 次各追加一行：文本匹配次数 | 400,000 |      20 | 对实际 `String.includes` 调用计数的回归；检查换词、换窗口、重排及清空 |
| 同一窗口追加场景，64 字符行                              | 15.4 ms | 11.0 ms | 本地 Node 临时基准，与 `6c8eab8` 的 renderer 对照                     |
| 同一窗口追加场景，1,024 字符行                           | 32.3 ms | 12.2 ms | 同上                                                                  |

时间样本测量已经准备缓存后的 20 次追加与查找，7 次运行中舍弃前 2 次、取剩余 5 次的中位数。它们不代表整页帧率或实机串口吞吐。结果顺序仍需要遍历窗口；优化消除的是旧文本的重复匹配，而非宣称整个查询为常数复杂度。网页导出使用 `Blob(chunks)`，省去额外拼接整份字符串。

## 验证边界

浏览器使用模拟串口和 Tauri 调用；归档测试验证配置、结果快照、忙碌状态和请求参数。未执行原生 Tauri 窗口／系统文件对话框验收、物理串口或长时间硬件压力测试。应用日志现在通过明确的上一段／下一段按钮阅读超出 300 行的内容；复制始终包含整个已加载尾部日志。归档中需要复制的源文件仍由现有后端按原路径读取，前端快照不保存固件或 Excel 的文件字节。
