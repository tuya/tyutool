# 日志阅读、更新恢复与页面加载优化

本轮基于 `yj/ui-theme-overhaul` 的 `bcee2cc` 实施五项已确认改进。

## 修改结果

| 场景               | 修改后的行为                                                                                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 横向阅读长日志     | 时间戳和 RX/TX 标签固定在原有左侧间距，背景覆盖正文高度；普通行与搜索行保持各自背景。离开串口页再返回，横向与纵向阅读位置保留。                                                                     |
| 更新检查失败       | 来源卡可单独重试，保留其他来源的结果；汇总区可重新检查。重复点击受到忙碌状态约束，关闭或离开后的旧请求不会覆盖新结果。重试完成不会夺走用户已移动的焦点。                                            |
| 多来源版本与安装包 | 汇总选择最高可用版本，同版本保留原有来源优先级。更新窗口与自动通知共用原生构建目标选择，避免从 WebView UA 猜测架构；无法匹配时可选择已发布的平台或打开发行页。直接下载按钮显示“下载安装包”。        |
| Unicode 查找       | `İ ERROR` 查找 `error` 完整高亮 `ERROR`；`İX` 查找 `x` 高亮 `X`。大小写展开后的字符位置映射回源文本，跨 ANSI 颜色片段与原有文本保留。映射仅在少数长度变化的行首次渲染时建立，原有有界缓存继续生效。 |
| 页面与弹窗加载     | 串口页、工具箱、批量工具及设置页延迟加载；更新与应用日志弹窗仅首次打开时加载。入口有加载状态，弹窗关闭后恢复按钮焦点，离开页面后的晚返回不会重新打开窗口。                                          |

固件工具首屏仍直接加载。未修改串口协议、原始字节、归档文件格式或设备所有权契约。

## 性能证据与取舍

入口 JS 实际文件大小从 **514,071 bytes（502.02 KiB）** 降到 **342,392 bytes（334.37 KiB）**，减少 **33.40%**。原有大 chunk 提示消失；Vite 配置导入扩展名提示仍存在。

本地 Chromium、1280×800、生产构建、无网络或 CPU 节流。优化前后分别创建新浏览器上下文，交替采样 7 次，舍弃前 2 次、取后 5 次中位数。串口后端使用本地 WebSocket 模拟，计时包括导航动画与等待界面元素出现。

| 本地场景             | 修改前 | 修改后 |
| -------------------- | -----: | -----: |
| 固件工具首屏         | 157 ms | 156 ms |
| 首次进入串口页       | 219 ms | 225 ms |
| 首次进入设置页       | 212 ms | 210 ms |
| 首次打开应用日志弹窗 |  45 ms |  66 ms |

这些耗时受本机负载影响，其他运行也出现过不同结果，不能据此保证启动提速。明确收益是减少首屏加载的代码；首次打开日志弹窗增加一次资源加载，已提供加载反馈。首屏请求记录确认未提前请求设置、串口、批量工具和两个弹窗的独立 chunk；基准流程未出现控制台错误。数据不代表实机串口吞吐或 GUI 帧率。

本次修改前构建保存在 `/tmp/tyutool-startup-before`，临时基准为 `/tmp/tyutool-startup-benchmark.mjs`，原始样本在 `/tmp/tyutool-startup-final.json`。构建入口体积按实际产物文件读取，未以构建中间阶段的 module 大小替代。

- 完整已确认浏览器回归：188 项通过。覆盖 en / zh-CN、light / dark、1024×680 / 1280×800；既有行高矩阵、搜索、历史分页、导出、结果卡、批量工具和设置交互继续通过。
- 新增 `tests/ui/update-log-loading.spec.ts` 和 `tests/ui/dialog-loading.spec.ts`，覆盖原生 ARM64 选择、识别失败后的手动选择、单来源重试、版本比较、慢加载、页面离开后的晚返回以及焦点恢复。旧 `LOG-03` 已纳入已确认套件。
- 实际查看了最小窗口暗色长日志与中文亮色平台选择窗口，复查前缀间距、背景高度、按钮文案与弹窗边界。截图保存在 `/tmp/tyutool-log-*` 和 `/tmp/tyutool-update-*`。
- Tauri 版本一致性、lint、scripts / UI 类型检查、build、`git diff --check` 通过。
- Rust fmt、全部 workspace 成员 clippy / test、`ts-rs` 与 bindings drift、`zip,excel,mock-chip,record-io,download` 特性组合 clippy / test 通过。serve / bridge 需要监听本地端口的测试在允许本地监听的环境中重跑通过；最初的 EPERM 属于沙箱限制。

## 验证边界

本轮包含 Linux Rust 编译和测试、浏览器模拟及生产构建测量。未执行原生 Tauri 窗口、各系统实际安装包、物理串口或长时间设备压力验收。平台选择测试验证的是原生接口返回值与下载 URL 的映射，未在每一种操作系统实机上运行。
