Settings

This page is the complete reference for the /settings page: every configurable option in one place, covering the update center, appearance & language, diagnostics & logs, serial logs, about, and how settings themselves persist.

1. Update center

The update center is the most prominent entry at the top of the Settings page, centralizing version checks and background update cadence:

  • Installed build: shows the version and badge of the currently installed build, so you can tell at a glance which version you're on.
  • Check for updates: desktop (Tauri) only. Clicking it opens the UpdateDialog, which checks for a new version immediately and shows the release notes — this is a manual trigger and always runs immediately, regardless of the interval below.
  • Automatic update checks: controls whether on app startup a silent check happens. It only fires if more than the selected interval has elapsed since the last successful check, so you're not bothered every launch. Options:
    • Off (manual checks only)
    • 1h (every 1 hour)
    • 6h (every 6 hours)
    • 12h (every 12 hours)
    • 24h (every 24 hours)
No auto-update on the web Auto-update relies on Tauri's updater plugin and is only available in the desktop app; the web build does not show the "Check for updates" button and the auto-check interval has no effect there.

2. Appearance & language

The appearance area groups the interface preferences you tweak most often:

  • Theme: a three-way segmented selector — Light / Dark / System.
    • The theme is applied to the DOM immediately, with no restart needed.
    • In System mode it follows the system color-scheme: when the OS switches between light and dark, the app follows in real time.
  • Language: the UI language, three options — Auto / 简体中文 / English.
    • Auto resolves from the browser / OS language: anything starting with zh uses Chinese, otherwise English.
    • The language is saved per device and takes effect immediately on change.
  • Serial port indicators: toggles the colored serial activity dots in the sidebar and toolbox entries, so you can see at a glance whether a port is actively sending or receiving.
Advanced UART settings aren't here Baud and other advanced UART parameters live in the settings modal on the Serial Debug page, not on Settings; see Serial Debug · Connect & UART config.

3. Diagnostics & logs

The diagnostics area puts debug logging and troubleshooting tools in one place:

  • Debug Log: master toggle. When off, the Rust backend's log level is set to off.
  • Log Level: available only when the debug log is on. The level is applied to the Rust backend's log::set_max_level via the set_log_level command. Options:
    • Error
    • Warn
    • Info
    • Debug
    • Trace (most verbose)
  • Open log folder: reveals the local log directory in your system file manager.
  • View logs: opens the in-app LogViewerDialog, so you can browse and search logs without leaving the app.
  • Export Logs & Report Issue: located inside the log viewer. Bundles the logs into a zip and opens a GitHub issue form pre-filled with the version and OS fields (desktop only).

How log files are written

On the desktop app, logs are written to the log directory by tauri-plugin-log, behaving the same as the CLI (see CLI):

  • Per-session naming: each launch writes its own file named tyutool-<timestamp>.log.
  • 10 MB rollover: once a single session log reaches 10 MB it rolls over to tyutool-<timestamp>-1.log, -2.log, and so on.
  • Startup pruning: old session files are pruned at startup, so they don't pile up indefinitely.
  • Log directory by platform:
    • Linux: ~/.local/share/tyutool/
    • macOS: ~/Library/Application Support/tyutool/
    • Windows: %APPDATA%\tyutool\
The level applies to the backend The log level acts on the Rust backend (via log::set_max_level), so it governs which logs get written to the log file — not what's displayed in the frontend UI.

4. Serial logs

The serial logs area is really a mirror entry for Serial Debug · auto-save, letting you configure session archiving without switching to the Serial Debug page:

  • Auto-save: when on, Serial Debug streams the entire session to disk. Turning it on for the first time without a directory chosen pops the directory picker automatically.
  • Save directory: a directory picker; shows the currently chosen directory (or — when none is set).
  • Timestamp format: toggles whether a timestamp is added to the auto-saved filename, to tell sessions apart.
Config is shared These settings are the same ones as Serial Debug's auto-save (sourced from the same store); changing them in either place is reflected immediately in the other.

5. About

The about area is a lighter, footer-style information block:

  • App version: shows the current tyutool version (matching the "installed build" in the update center).
  • Open-source licenses: opens the project's LICENSE page.

6. Persistence

Settings persist as follows and are restored on the next launch:

  • Desktop (Tauri): written to settings.json (managed by tauri-plugin-store). On startup it's loaded asynchronously from that file, and the theme is re-applied to the DOM once loading finishes.
  • Web: written to the browser's localStorage.
  • Theme: in either runtime the theme is applied to the DOM; in System mode it also listens to the system color-scheme and follows it live.
Keys match The key names inside the desktop's settings.json map one-to-one to the localStorage keys on the web (theme, language, debug-log toggle, etc.), which makes inspection and migration straightforward.
