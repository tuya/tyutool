Batch Auth · Operator Guide

This page is for operators using tyutool to batch flash and authorize: how to prepare, how to operate, and what to do when something breaks. No technical background required.

Wrong page? If you are a firmware developer (you need to know what your firmware must implement to be batch-authorizable), see Batch Auth · Firmware Developer Guide.

1. What this tool does

It processes many devices at once — plug multiple devices into your computer's serial ports, click one button, and tyutool simultaneously flashes firmware and writes the credentials each device needs to connect to the cloud. You don't type the credentials by hand; they're read row-by-row from an Excel spreadsheet.

Desktop app only This feature relies on system hardware capabilities and is only available in the desktop tyutool app, not on the web.

2. What to prepare beforehand

  • The desktop tyutool app: make sure you're running the desktop application, not the web version.
  • An auth-code Excel sheet (.xlsx): these are credentials purchased from Tuya. The sheet needs at least two columns: UUID and AuthKey (column names are case-insensitive). tyutool fills in the other columns (status, MAC, timestamp, etc.) automatically.
  • Devices + serial cables: connect each device to the computer via a USB-to-serial adapter; each device occupies one serial port.
  • Serial drivers: install the driver for your USB-to-serial chip (CH340 / CP2102 / FT232, etc.), otherwise the computer won't see the port.
  • The firmware to flash (optional): if this step also flashes firmware, have the .bin file ready, or use the official auth firmware that tyutool can download.
Auth codes are valuable UUID and AuthKey are paid credentials, one code per device. Keep the Excel file safe and never leak it in chats or screenshots.

3. First time you enter

The first time you open the batch auth page, a disclaimer dialog appears reminding you that this feature performs irreversible operations. Acknowledge it to continue. Checking "don't show again" suppresses it next time; clicking Cancel returns you to the toolbox without entering the page.

4. How a full run works

  1. Pick the chip: choose your device's chip (e.g. esp32, t5ai; pick other for auth-only without flashing).
  2. Set baud rates: set the flash baud and the auth baud separately; leave defaults if unsure.
  3. Pick firmware (only if flashing): turn on "flash firmware", choose a local .bin, or use "default" to download the official auth firmware (filtered by chip, with a version dropdown and download progress).
  4. Pick the auth-code Excel sheet: selecting it immediately shows total / used / in-progress / remaining. Confirm "remaining" is greater than 0 — otherwise the Start button stays disabled.
  5. Set the conflict policy: Skip or Overwrite when a device already has auth.
  6. (T5AI only) Pick the storage mode: KV (rewritable) or OTP (write-once, irreversible — see Safety).
  7. Auto-assign ports: click "Auto-assign" to add all available serial ports as slots.
  8. Start: click "Start" to begin the batch. If there are many idle ports (> 8), a confirmation dialog appears to avoid accidental launches.
  9. Watch the dashboard: track the cumulative flash/auth stats and the current batch progress in real time; a completion banner appears at the end (all-success / all-failed / partial / all-skipped).
  10. Check the results: inspect each port's status row by row; for failures, click the error to see details and retry.
Want to peek at the devices first? Click "Read All" on the toolbar to run a read-only probe (read MAC, read existing auth) on non-active slots — it writes nothing, great for a pre-batch check.

5. Reading the results

Each port in the batch occupies one row showing:

  • A status badge (colored) telling you the row's current state. Common statuses:
StatusWhat it means
doneThis device flashed and authorized successfully — it's a good unit.
failedA step errored. Click the error message for details; you can retry.
skippedThis device already had auth; skipped per your "skip" policy.
no_codeAuth codes ran out; no code was assigned to this device.
Others (processing)Anything showing "reading / flashing / authorizing" is still processing; just wait for it to finish.
  • Progress bar: shown during the flash phase, advancing per phase.
  • MAC / UUID: shown on the row once read.
  • Error message: shown on failure; click it for details and copy support, handy when reporting an issue.

6. What to do when something breaks

Port doesn't appear / won't open

  • Try a different USB cable or USB port (many issues are cable or contact related).
  • Make sure the serial-chip driver is installed (CH340 / CP2102 / FT232).
  • Close other programs using the serial port (other serial-debug tools, Arduino IDE, etc.) — they may be holding it.
  • More troubleshooting in FAQ · Connections / Ports.

All failures / lots of failures

  • Get it working on a single device first, then commit to the whole batch.
  • Lower the baud rate (e.g. down to 115200) — packet loss at high baud causes failures to spike.
  • Insufficient power also causes batch failures — check USB power, use external power if needed.

Excel errors (locked / invalid)

  • "File locked": close Excel / WPS first, then reselect the sheet. During a batch run tyutool locks the file to prevent conflicts.
  • "Invalid sheet": check the sheet really has UUID and AuthKey columns with the correct lengths.

Need more detailed logs / to report an issue

Failure details are in each row's error dialog; for deeper troubleshooting, follow FAQ · How to report a bug to export logs.

7. Safety

Batch authorization is the only feature in tyutool that performs irreversible hardware operations. Keep these two rules in mind:

Rule one: OTP mode is write-once and irreversible If you select OTP storage mode (T5AI only), credentials are burned into the chip once and can never be erased or modified. One wrong setting (wrong chip, wrong firmware, wrong codes) ruins the whole batch. So: before using OTP, run the full flow end-to-end on a single device to validate it; only commit the whole batch once confirmed correct.
Rule two: devices showing the "cancelled-after-write" danger badge must be set aside If a device is cancelled after the auth write may have already landed, it shows a physical-quarantine danger badge — meaning the auth may already have been written and the device's state is uncertain. Such devices must not be treated as good units and must not be re-run through the batch directly; set them aside and verify each one individually before deciding what to do.
Pre-batch checklist Before starting the batch, confirm each item: the chip is correct, the firmware version is correct, the auth sheet is validated with enough "remaining", and the conflict policy is as intended; if using OTP, validate on a single device first.
