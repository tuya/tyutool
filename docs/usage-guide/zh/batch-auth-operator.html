批量授权 · 操作员指南

本页写给使用 tyutool 进行批量烧录授权的操作员，按"照着做"的顺序组织。不需要任何技术背景。

走错页了？ 如果你是固件开发者（需要知道固件要实现哪些功能才能被批量授权），请看 批量授权 · 固件开发者必读。
1开工前清单→ 2配置→ 3接线与启动→ 4核对结果· 出错速查 安全铁律

1. 这个工具做什么

把很多台设备一次性处理完：把多块设备插到电脑的多个串口上，点一下"全部开始"，tyutool 就会同时给它们烧录固件并写入上网所需的授权码。授权码不用手敲，从一份 Excel 表里自动一行行读取。

和固件开发者对齐：配置交接单

批量要用的每一项配置都应由固件开发者给出、由操作员照单核对——不要靠猜。建议把下表复制到工单或群里，开发者逐项填写，操作员开工前逐行核对：

配置项固件开发者填写操作员核对
芯片型号目标芯片（如 esp32 / t5ai；只授权不烧录写 other）批量页"芯片"选择与交接单一致
操作模式只授权还是先烧固件再授权（即开发者页的路径 A / 路径 B）"烧录固件"开关：只授权 = 关，先烧再授 = 开
固件文件与版本文件名 + 版本号；用官方 auth-firmware 的注明版本选中的固件文件名/版本一致（归档的 batch-summary.json 会记录 SHA256，可事后核查）
烧录波特率推荐值（按芯片）一致；想降波特率先和开发者确认
授权波特率固件 shell 的波特率（通常 115200）一致
存储模式KV 或 OTP（仅 T5AI；选 OTP 必须显著标注）一致；OTP 必须先单台验证（见安全铁律）
冲突策略跳过 / 覆盖（OTP 只能跳过）一致
授权表用哪一份 Excel、本批预计数量文件选对；界面"剩余" ≥ 本批新设备数量（恢复/重试已登记设备不占新码）
接线烧录/授权口的位置说明（T5 勿接日志口）按说明接线
MAC 唯一性确认每台设备已烧录全球唯一、互不重复的 MAC，并注明 MAC 在哪个环节个性化知悉：tyutool 不校验 MAC 是否与其他设备冲突。授权码与 MAC 绑定，重复的 MAC 会让不同设备共用同一个授权码，设备在涂鸦平台将无法正常识别
单台试通已按固件自测清单手工测试通过产线环境再单台跑通一次，再小批量试跑
特殊事项默认 MAC 处理、供电要求、其他注意点已逐条知悉
对不上怎么办 任何一项与交接单不一致，先停下来找固件开发者确认，不要按自己的理解改配置——尤其是存储模式和固件版本。

3. 操作流程

打开 tyutool，左侧导航进入工具箱 → 批量烧录授权。

第一次进入 会弹出免责声明对话框（本功能涉及不可逆操作），点继续即可进入；勾选"不再提示"后下次不弹。想再看一次：设置 → 关于 → "重新显示批量授权风险提示"。

阶段一 · 配置（展开顶部"配置"面板）

  • ① 选择芯片型号：如 ESP32、T5AI；只授权不烧录选 other。
  • ② 设置烧录波特率。
  • ③ 设置授权波特率：不确定就用默认值。
  • ④ 是否烧录固件：开启后会先烧录固件、再授权。
  • ⑤ 固件文件：本地文件 / 默认授权固件，二选一。
  • ⑥ 本地文件：选择固件位置；默认授权固件：选择版本（建议使用最新版），下载就绪后显示"固件已就绪"。
  • ① 选择授权表（.xlsx）。
  • ② 查看表中授权码信息是否符合预期：总计 / 已用 / 占用中 / 剩余。给新设备分码需要"剩余" > 0；仅恢复/重试已登记设备时剩余 0 也可启动（tyutool 会按 MAC 找回各自原来的码）。
  • ③ 遇到已带授权的设备怎么办：跳过（推荐）还是覆盖。

（仅 T5AI）选存储模式：芯片选 T5AI 时，批量授权配置里会多出"存储模式"选项（上图为 ESP32，无此项）。KV 可重写；OTP 写一次不可逆，用前必读 安全铁律。

阶段二 · 接线与启动

建议一步一步来：先小批量试跑 不要第一次就把整批设备全插上。推荐节奏：先用 1 台设备完整跑通（配置、烧录、授权、核对全流程）→ 再用 2～4 台小批量试跑，确认每行都是 done → 最后再上整批。前面多花几分钟，能避免整批返工。

接好设备（每台设备一个串口；T5/T5AI 务必接烧录/授权口）后，只需两步：

  1. 点 ① 自动分配：扫描并把所有可用串口加为处理插槽，每口一行、状态"空闲"。
  2. 点 ⑥ 全部开始：开始整批处理；空闲端口较多（> 8）时会先弹确认框防误点。
按启动键前，最后 30 秒检查 各项配置和配置交接单逐行对上了吗？芯片型号对？固件版本对？授权表"剩余"够？冲突策略符合预期？如果用 OTP——先用一台设备完整跑通验证过了吗？
工具栏其他按钮（按需使用） ② 串口过滤——屏蔽不参与批量的串口（角标 = 已屏蔽数量）；③ 全部读取——只读摸底（读 MAC、读现有授权，不写入任何内容），适合启动前确认设备现状；④ 取消——停掉进行中的批次；⑤ 重试失败——一键重跑所有失败行；⑦ 单口"读取"——只探测这一台。

阶段三 · 等待与核对

  1. 看仪表盘等完成：实时显示烧录/授权累计统计和当前批次进度；整批结束会出完成横幅（全部成功 / 全部失败 / 部分成功 / 全部跳过）。
  2. 逐行核对：每个端口一行，按状态徽标判断好坏（见下一节）；失败的点错误信息看详情并重试。
  3. 归档（整单跑完时）：一份授权表的任务全部跑完后，点完成横幅上的"归档"按钮一键存档；分多轮跑的中间轮次不用归档（详见归档说明）。

4. 看懂结果

每个端口一行，一行里有：状态徽标（带颜色）、烧录阶段的进度条、读取到的 MAC / UUID，以及失败时的错误信息（点开可看详情并复制）。判断标准就一张表：

状态什么意思要做什么
done（完成）烧录和授权都成功。好品，正常流转。
failed（失败）某一步出错了。点错误信息看详情，可重试。
skipped（跳过）设备已有授权，按"跳过"策略略过。确认符合预期即可。
no_code（无码）这是台新设备（表里没登记过），且"剩余"已经是 0，分不到新码。补充"剩余"充足的授权表后重跑这台；表里已登记的设备不受影响。
其他（处理中）"正在读取 / 正在烧录 / 正在授权"等。还在跑，等它完成。

整单跑完，归档留底

先分清两个词，避免歧义：点一次"全部开始"叫一轮；一份授权表对应的整个生产任务叫一单（一单往往分很多轮跑完，比如 4 个串口 × 250 轮 = 1000 台）。归档以"单"为单位：一份授权表 = 一个档案文件夹，整单跑完（或中途要换表时）归档一次即可——分多少轮不影响，因为每台设备的状态、MAC、时间都实时写回了授权表，Excel 副本就是全量台账。

一键归档 完成横幅右侧有"归档"按钮：选一个存放目录，tyutool 会自动创建带时间戳的档案文件夹（如 batch-archive_20260717-143205_esp32/），存入授权表副本（全量台账）、固件文件（含 SHA256 校验值）、日志 logs.zip、摘要 batch-summary.json（配置、环境、统计）和 batch-slots.csv。注意：summary 里的 lastRun 和 csv 只是最后一轮的现场快照——查全量始终以 Excel 副本为准。

档案的价值：授权码是花钱买的，这份档案就是"哪台设备用了哪个码"的台账，日后出货追溯、售后定位全靠它。点"归档"后，档案文件夹里有：

档案内容用途
授权表 Excel 副本全量台账：本单每台设备的状态、MAC、时间都在表里。归档后不要再手工改动。
固件文件回答"当时刷的到底是哪个固件"；SHA256 校验值记在 batch-summary.json 里。
logs.zip本次会话的全部日志，排查问题的原始依据。
batch-summary.json当时的完整配置（芯片 / 波特率 / 固件 / 策略 / 存储模式）、环境（版本 / 系统）、统计与最后一轮明细。
batch-slots.csv最后一轮每口的结果与错误信息，Excel 可直接打开。
完成横幅截图本单成绩单，一目了然。
档案是敏感资料，防泄露 档案里的授权表副本含 UUID 和 AuthKey（花钱买的凭据），日志里也可能带设备信息。请存放在受控位置（受限访问的目录 / 内部网盘），不要发到聊天群、公开网盘或工单附件里整包外传；需要给人排查时，只提供日志和错误信息，授权表一律不外发。

5. 出错速查

按现象找处理办法：

现象怎么处理
应用打不开 / 窗口白屏安装类问题：Linux 白屏见 FAQ · Linux 窗口空白；macOS 提示"无法验证开发者"见 FAQ · Gatekeeper 拦截。
端口没出现 / 打不开换一根 USB 线、换一个 USB 口；确认驱动已装好；关掉其他占用串口的程序（串口调试软件、Arduino IDE 等）。更多见 FAQ · 连接/端口。
全部失败 / 大量失败先用单台设备试通再投整批；把波特率降到 115200；检查 USB 供电，必要时外接供电。
Excel 提示"文件被占用"先关掉 Excel / WPS 再重新选表（批量运行期间 tyutool 会锁住文件防冲突）。
Excel 提示表无效检查表里是否有 UUID 和 AuthKey 两列，且长度正确。
需要详细日志 / 报问题先按下面的清单把现场保存好；导出日志见 FAQ · 如何反馈 bug。

报问题前，先把现场保存好

最快的办法：趁现场还在，直接点完成横幅上的"归档"——错误明细、日志、授权表副本、配置与环境信息一次全部存下（见归档说明；单条错误全文也可以点失败行的错误 → 详情 → 复制）。归档之外，只需再手工补三样：

  • 界面截图：失败行所在的端口列表，要能看到端口号、状态徽标、停在哪一步。注意遮住 AuthKey——UUID 可以保留，用来对上是哪一行。
  • 问题设备实物：贴标签单独放好，别混回好品堆——尤其是带危险徽标的设备（见安全铁律）。
  • 一句话现象描述：什么时候、做到哪一步、第几台开始出错；用外置 USB 转串口适配器的，注明芯片型号（CH340 / CP2102 等）。
别拖，也别泄露 应用会自动清理旧日志，跑新批次也会覆盖现场——出错后当天就归档。外发排查材料时只给日志和错误信息：档案里的授权表副本含 AuthKey，不要整包外传（见归档说明的防泄露提示）。

6. 安全铁律

批量授权是 tyutool 里唯一会触发不可逆硬件操作的功能。记住两条铁律：

铁律一：OTP 模式写一次不可逆 如果存储模式选了 OTP（仅 T5AI 可选），授权码会一次性烧进芯片，永远无法擦除或修改。一旦配错（芯片型号错、固件错、授权码错），整批设备都会被毁掉。所以：用 OTP 之前，务必先用一台设备把整个流程完整跑通验证，确认无误后再批量。
铁律二：带"已写入后取消"危险徽标的设备必须单独放一边 如果某台设备在授权可能已经写入之后才被取消，它会显示一个物理隔离危险徽标——授权可能已写进去，设备状态不确定。这种设备不能当成好品，也不要直接重新跑批量，必须单独拿出来核实清楚后再决定怎么处理。
