命令行工具

tyutool 是一个命令行工具，用于通过 UART 烧录、读取和管理涂鸦生态 IoT 设备固件。本页把 docs/cli.md 的完整 CLI 参考移植成统一样式的 HTML 版本——内容一字不少，仅做了更易读的排版（提示框、表格、代码块）。

1. 什么时候用 CLI

当你需要脚本化、在 CI 里跑批、在无桌面的服务器上操作，或者你更习惯终端而不是 GUI 时，CLI 是最顺手的入口。它和桌面应用共享同一套 tyutool-core 烧录逻辑，能力与 GUI 对等，且可被管道、cron、脚本直接驱动。

2. 安装

从 GitHub Releases 页面下载最新版本的发布二进制文件，并将其放到你的 PATH 中。

下载最新 release 二进制 → 放到 PATH 上

3. 全局选项

选项说明
--verbose把开发者诊断日志写到 stderr（日志文件里始终会写）。
--plain强制输出纯文本（仅 ASCII，无 spinner / 进度条）。

日志文件位置：每次运行都会写到一个独立的会话文件 tyutool-<timestamp>.log；单个会话日志上限 10 MB，超出后滚动为 tyutool-<timestamp>-1.log、-2.log…… 旧的会话文件在启动时会被清理（pruning）。

  • Linux：~/.local/share/tyutool/tyutool-<timestamp>.log
  • macOS：~/Library/Application Support/tyutool/tyutool-<timestamp>.log
  • Windows：%APPDATA%\tyutool\tyutool-<timestamp>.log
滚动文件命名 当单次会话日志超过 10 MB 时，会滚动到 tyutool-<ts>-1.log、-2.log……；<ts> 是本次会话的时间戳，N 是滚动序号。每次启动 tyutool 时还会修剪旧的会话文件。

端口选择（带 -p/--port 的命令）：省略 -p 时，若只有一个可用端口，会自动使用它；若存在多个端口，在交互式终端上会提示你选择一个，而在非交互环境（CI、管道）下命令会报错并要求你显式传 -p。

4. 子命令

下列 10 个子命令按字母/逻辑顺序给出。每个子命令含：用法行（<pre>）、参数表（<table>）、示例（<pre>）。参数与默认值与 docs/cli.md 完全一致。

write — 烧录固件到设备

tyutool write -d <DEVICE> -f <FILE> [-p <PORT>] [-b <BAUD>] [-s <START>] [--end <END>]
参数简写说明默认值
--device-d芯片名（见支持列表）必填
--file-f固件 .bin 文件路径必填
--port-p串口（如 /dev/ttyUSB0、COM3）自动检测第一个端口
--baud-bUART 波特率按芯片不同（见下表）
--start-sFlash 起始地址（十六进制，如 0x0）0x00000000
--endFlash 结束地址（十六进制）；默认为 start + 文件大小计算得出

示例：

tyutool write -d bk7231n -f firmware.bin -p /dev/ttyUSB0

read — 从设备读取 Flash 内容

tyutool read -d <DEVICE> -f <FILE> [-p <PORT>] [-b <BAUD>] [-s <START>] [-l <LENGTH>]
参数简写说明默认值
--device-d芯片名必填
--file-f输出 .bin 文件路径必填
--port-p串口自动检测
--baud-bUART 波特率按芯片不同
--start-s读取起始地址（十六进制）0x00000000
--length-l读取长度（十六进制）0x200000

示例：

tyutool read -d bk7231n -f flash_dump.bin -l 0x200000

erase — 擦除设备上的 Flash 区域

tyutool erase -d <DEVICE> [-p <PORT>] [-b <BAUD>] [-s <START>] [-l <LENGTH>]
参数简写说明默认值
--device-d芯片名必填
--port-p串口自动检测
--baud-bUART 波特率按芯片不同
--start-s擦除起始地址（十六进制）0x00000000
--length-l擦除长度（十六进制）0x200000

擦除区域为 start … start + length。某些芯片会把该区域对齐到其扇区大小（sector size）。

示例：

tyutool erase -d bk7231n -s 0x0 -l 0x200000

list-ports — 列出可用串口

tyutool list-ports [--json]
参数说明
--json输出端口对象的 JSON 数组，而非制表符分隔的列。

默认输出为制表符分隔的列：path、vid:pid、usb_interface、port_role、display_name。

加 --json 时，每个条目包含 path、name、usbVid、usbPid、usbSerial、usbInterface、portRole（未知字段为 null）。

reset — 通过 DTR/RTS 硬件复位设备

tyutool reset [-p <PORT>] [-d <DEVICE>]
参数简写说明默认值
--port-p串口自动检测
--device-d芯片系列（影响复位时序）bk7231n

authorize — TuyaOpen 设备授权

tyutool authorize [-p <PORT>] [-d <DEVICE>] [--uuid <UUID>] [--authkey <AUTHKEY>]
参数说明
-p / --port串口（默认：自动检测）
-d / --device芯片类型——选择按芯片而定的授权时序（如 esp32、t5ai）。可选；省略则使用通用时序。
--uuid要写入的 UUID（省略则只读取当前授权状态）
--authkey要写入的 AuthKey（省略则只读取）

写入授权时必须同时传 --uuid 和 --authkey。只传其中一个会被拒绝并报错。两者都不传则执行只读的 auth-read。

读取当前授权状态：

tyutool authorize -p /dev/ttyUSB0
tyutool authorize -p /dev/ttyUSB0 -d esp32

写入新授权：

tyutool authorize -p /dev/ttyUSB0 -d esp32 --uuid abc123 --authkey def456

update — 自更新二进制

tyutool update [--check] [--source <github|gitee>]
参数说明
--check只检查版本，不下载。
--source更新源（默认 github，国内用 gitee）。

serve — WebSocket 服务器（开发/IDE 模式）

tyutool serve [--port <PORT>]

启动一个本地 WebSocket 服务器，用于基于浏览器的烧录操作（供 tuyaopen-ide 使用）。默认端口：9527。

completions — 生成 shell 补全脚本

tyutool completions <SHELL>

<SHELL> 取值之一：bash、zsh、fish、powershell、elvish。脚本打印到 stdout（无 banner / 日志噪声），可直接 source。

示例：

# Bash（当前 shell）
source <(tyutool completions bash)

# Zsh（安装到 $fpath 里的某个补全目录）
tyutool completions zsh > ~/.zfunc/_tyutool

# PowerShell（Windows）
tyutool completions powershell | Out-String | Invoke-Expression

usb-port-survey — USB/串口元数据转储

tyutool usb-port-survey

输出包含所有端口原始 USB 元数据的 JSON。用于跨操作系统排错调试。

6. 输出模式

Rich 模式（交互式 TTY）：spinner、带 ANSI 颜色的进度条、✓ 对勾。

Plain 模式（CI / 管道 / 重定向）：固定宽度的阶段标签、长阶段每 10% 输出一个百分比刻度、仅 ASCII 的分隔符。

Plain 模式输出示例：

tyutool v3.0.7  linux/x86_64

write  BK7231N  /dev/ttyUSB0  921600
  File   firmware.bin  1.8 MiB
  Range  0x00000000 -> 0x001CE400

Handshake         OK
Erase             10%  20%  30%  40%  50%  60%  70%  80%  90%  OK
Write [1/2]       10%  20%  30%  40%  50%  60%  70%  80%  90%  OK
Write [2/2]       10%  20%  30%  40%  50%  60%  70%  80%  90%  OK
Verify            OK
Reboot            OK
Flash OK  3.2s

成功退出码为 0，失败或取消时为非零。

取消（Cancellation） 在 write、read、erase 或 authorize 期间按 Ctrl+C，会设置一个取消标志，使任务优雅退出（关闭串口并报告 Cancelled），而不是在传输中途把进程杀掉。
