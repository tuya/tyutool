批量烧录授权

本页是 /batch 页面的完整参考：在多个 USB-串口上并行烧录 + 授权，授权码由一份 .xlsx 表格驱动。这是 tyutool 里最复杂的功能，涉及不可逆的 eFuse 操作，请务必阅读第 9 节的安全提示。

1. 适用场景

当你需要一次性处理大量设备——把多块开发板插到多个 USB-串口上、并行烧录固件并写入授权码——批量烧录授权页就是为此设计的。授权码从一份 Excel 表格（.xlsx）逐行读取，每个空闲端口分配到一个待授权设备。

  • 并行多端口：所有非屏蔽端口可同时作为插槽（slot）参与批量任务。
  • 表格驱动授权：授权码不靠手动输入，而是来自 .xlsx，启动前会先校验总数 / 已用 / 进行中 / 剩余。
  • 仅桌面端（Tauri）可用：Web 模式下页面会提前返回，不提供任何批量能力。
Web 端不可用 串口扫描、并行烧录与 eFuse 操作都依赖 Tauri 的系统能力，仅在桌面应用里可用。Web 端进入本页会直接提前返回，不显示任何批量控件。

2. 免责声明

由于批量授权可能触发不可逆的 eFuse 烧写，本页在首次访问时会弹出免责声明对话框：

  • 首次访问弹窗：说明批量授权的风险（尤其是 OTP + eFuse 锁不可逆），需要你确认知晓后才继续。
  • 不再提示（don't show again）：勾选后该选择会写入 localStorage，之后不再弹出。
  • 取消即返回：在免责声明对话框上点取消会直接退回 /toolbox，不会进入批量页面。
请认真阅读免责声明 免责声明不是走过场——一旦启用 OTP 存储模式并打开 eFuse 锁，烧写不可撤销。请确认你理解第 9 节的全部风险后再勾选“不再提示”。

3. 配置 — 共享

共享配置区对所有插槽统一生效，包括芯片型号、波特率与固件来源：

  • 芯片（Chip）：选项仅限 esp32、t5ai、other。其中只有 esp32 与 t5ai 是可烧录芯片（带 flash 插件）；other 仅用于授权，不能烧录固件。
  • 烧录波特率（Flash baud） 与 授权波特率（Auth baud）：分别用于固件烧录阶段与授权阶段。
  • 烧录固件开关（Flash firmware）：仅在可烧录芯片（esp32 / t5ai）下可用。打开后每个端口会先烧录固件再授权；关闭则只授权。固件来源有两种：
    • 本地（Local）：浏览选择本地 .bin 文件。
    • 默认（Default）：从线上 auth-firmware.json 清单下载——清单会按所选芯片过滤出可用固件，提供版本下拉选择，并显示下载进度。
芯片决定能做什么 esp32 与 t5ai 可烧录 + 授权；other 只能授权。切换芯片时，烧录固件相关控件会按芯片能力自动启用或禁用。

4. 配置 — 授权

授权配置区围绕授权码表格与存储模式展开：

  • Excel 表格（.xlsx）：选择授权码表后立即触发校验，显示 总数 / 已用 / 进行中 / 剩余。若剩余 = 0或文件无效，启动按钮禁用。
  • 冲突策略（Conflict policy）：当目标设备已存在授权时如何处理 —— Skip（跳过）或 Overwrite（覆盖）。
  • 存储模式（Storage mode）：仅 T5AI 可选 —— KV（键值区，可重写）或 OTP（一次性存储区）。选择 OTP 会显示不可逆警告。
  • OTP eFuse 锁开关（lockOtpAfterAuth）：仅在 T5AI + OTP 下出现。打开后，授权写入完成后会烧写 eFuse，永久锁定 OTP 区，不可逆。
危险：OTP + eFuse 锁不可逆 当存储模式为 OTP 且打开 lockOtpAfterAuth 时，每个设备授权完成后会烧写 eFuse，把 OTP 区永久锁死——这一步不可撤销，无法通过任何手段恢复或重写。在批量场景下，一次错误配置会连锁毁掉整批设备。请仅在完全确认芯片型号、固件、授权码无误后再启用。

作为兜底保护，lockOtpAfterAuth 在每次应用启动时强制重置为 false，并在离开 (t5ai, otp) 任一前置条件（即切到非 T5AI 芯片或切回 KV 存储模式）时同样强制重置为 false。也就是说，你每次想启用 eFuse 锁都必须重新主动打开它，绝不会因为上次忘关而延续到下一次。

5. 仪表盘

仪表盘是一个置顶面板，实时汇总整批任务的状态：

  • 烧录累计统计：环形图（donut）+ 总数 / 成功 / 失败计数，并提供重置按钮（重置累计计数，不影响当前批次）。
  • 授权累计统计：与烧录统计结构相同——环形图 + 总数 / 成功 / 失败 + 重置。
  • 当前批次统计：显示本批次的活动 / 完成 / 失败数量，并带实时计时器（自批次启动起计的已用时长）。
  • 完成横幅（Completion banner）：整批结束时显示，按结果分为 all-skipped（全部跳过）/ all-success（全部成功）/ all-failed（全部失败）/ partial（部分成功），可手动关闭。

6. 工具栏

工具栏提供对整批插槽的批量操作：

  • 自动分配（Auto-assign）：把所有非屏蔽端口一键加为插槽。
  • 筛选（Filter）：打开端口筛选弹窗，选择哪些端口参与；按钮上的徽标显示当前被屏蔽的端口数。
  • 全部读取（Read All）：对非活动插槽执行只读的 MAC / 授权探测（不写入任何内容）。
  • 取消（Cancel）：取消当前进行中的操作。
  • 重试（Retry）：对状态为 failed 或 no_code 的插槽重试。
  • 启动（Start）：启动整批任务；当空闲端口 > 8时会弹出确认对话框，避免误启动大量端口。
启动前的硬性条件 启动按钮在剩余授权码 = 0、授权表无效、或没有可分配端口时均会保持禁用。

7. 每个端口 / 插槽

每个参与批量任务的端口占一行插槽（slot row），显示该端口的完整状态：

  • 端口名 与 状态徽标（带颜色），状态取值见下表。
  • 进度条：仅在烧录阶段显示，按分阶段进度推进。
  • MAC 与 UUID：读取到后显示。
  • 错误信息：失败时显示；点击错误可打开详情对话框并支持复制。
  • 逐行操作：读取（Read）；活动中的行可取消（Cancel）；失败的行可重试（Retry）。
  • 右键：弹出菜单可屏蔽该端口（Block port）。

插槽状态徽标取值如下：

状态含义
idle空闲，尚未启动或已结束回到就绪。
reading正在读取（MAC / 授权探测）。
flashing正在烧录固件。
reading_mac正在读取 MAC。
authorizing正在写入 / 校验授权。
done本插槽完成（烧录 + 授权均成功）。
failed某一步失败。
skipped因冲突策略被跳过。
no_code没有可用授权码可分配。
危险：cancelledAfterWrite 设备必须物理隔离 如果在授权写入可能已落地之后才取消该端口，该插槽会被打上 cancelledAfterWrite 标志并显示物理隔离危险徽标。这意味着授权写操作可能已经在取消前完成，设备状态无法确定。此类设备必须物理隔离，不得直接返回良品池或重新流入批量流程——请单独核实其授权状态后再决定处置。

8. 操作模式

根据芯片能力与配置，每个端口会进入以下两种模式之一：

  • flash-then-auth：满足可烧录芯片 + 烧录固件开关打开 + 固件路径已设置时启用。每个端口的完整流程为：烧录固件 → 读取 MAC → 读取授权 → 写入授权 → 校验。
  • auth-only：不满足上述条件时（例如芯片为 other，或固件开关关闭）。每个端口的流程为：读取 MAC → 读取授权 → 写入授权 → 校验。

所有阶段的进度都通过事件通道实时推送到前端：

  • batch-flash-progress —— 批量烧录进度。
  • batch-auth-progress —— 批量授权写入进度。
  • batch-auth-read-progress —— 批量授权读取进度。
  • auth-firmware-download-progress —— 默认固件下载进度。
模式是按端口自动判定的 你不需要手动选择模式——tyutool 会根据共享配置里的芯片、固件开关与固件路径，自动为每个端口判定走 flash-then-auth 还是 auth-only。

9. 安全提示

批量烧录授权是 tyutool 里唯一会触发不可逆硬件操作的功能。请牢记以下两条铁律：

铁律一：OTP + eFuse 锁不可逆 存储模式选 OTP 并打开 lockOtpAfterAuth 后，每个设备授权完成都会烧写 eFuse，把 OTP 区永久锁死，任何手段都无法恢复或重写。批量场景下一次错配会毁掉整批设备。

兜底保证：lockOtpAfterAuth 在每次应用启动时强制重置为 false，并在离开 (t5ai, otp) 任一前置条件（切到非 T5AI 芯片、或切回 KV 模式）时同样强制重置为 false。你每次启用 eFuse 锁都必须重新主动打开，绝不会因上次忘关而延续。
铁律二：cancelledAfterWrite 设备必须物理隔离 若在授权写入可能已落地之后才取消某端口，该插槽会被标记 cancelledAfterWrite 并显示物理隔离危险徽标——授权写可能已在取消前完成，设备状态无法确定。此类设备必须物理隔离，不得返回良品池或重新进入批量流程，需单独核实后再处置。
批量前的检查清单 启动整批任务前，请逐项确认：芯片型号正确、固件来源与版本无误、授权表已校验且剩余充足、冲突策略符合预期；若启用 OTP + eFuse 锁，请先用单台设备验证完整流程，再投入批量。
