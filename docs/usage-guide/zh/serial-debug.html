串口调试

本页是 /serial-debug 页面的完整参考：一个完整的串口终端 / 日志监视器，覆盖连接与 UART 配置、设备复位、ASCII / Hex 日志视图、发送栏、Hex 弹窗、关键词过滤标签，以及自动释放与自动保存。

1. 总览

/serial-debug 是一个完整的串口终端，既可以用来观察设备实时打印的日志，也可以向设备发送指令或数据。整个界面由顶部连接栏、中间的日志视图、底部的发送栏，以及右侧的过滤标签/设置区组成。

页面带有一个保活（keep-alive）机制：当你从串口调试页跳到其他页面（例如去 固件烧录看一下进度）再回来时，后台的 RX 接收流不会中断，回来后仍能继续看到设备在这段时间打印的内容，不会因为切换页面而丢数据。

与固件烧录页共用串口 串口调试页与固件烧录页共用同一批串口，同一时刻只能由一方占用某个端口。关于让端口在不同页面之间切换的机制，见下方自动释放。

2. 连接与串口配置

顶部连接栏用于建立和管理串口连接：

  • 串口选择：下拉列出当前可用串口，每次打开会重新扫描。
  • 连接 / 断开：手动打开或关闭与所选串口的链路。
  • 状态指示：显示当前端口是已连接 / 未连接 / 被其他页面占用。

常规参数（波特率等）直接在连接栏选择；高级 UART 设置则放在设置弹窗里，包含：

参数可选值说明
波特率（Baud）9600–921600 档位 + 自定义未手动覆盖时，默认取当前所选 flash 芯片的日志波特率（见芯片清单）。
数据位（Data bits）5 / 6 / 7 / 8每帧数据位数。
校验位（Parity）none / odd / even无 / 奇校验 / 偶校验。
停止位（Stop bits）1 / 1.5 / 2每帧停止位数。
波特率跟随芯片 如果你只是想看某款芯片的启动日志，无需手动查它的日志波特率——只要先在烧录页选好芯片型号，串口调试页的波特率就会自动对齐到该芯片的日志波特率；手动改过之后则以你的设置为准。

3. 设备复位

串口调试页支持通过 DTR / RTS 信号线复位设备，方便在不拔插的情况下让设备重启、重新打印启动日志。

  • 复位当前会话端口：直接对当前连接的串口拉一次 DTR/RTS 复位序列。
  • 复位其他控制端口：当设备的复位引脚并不在日志串口上时，可以通过一个运行时芯片 id（runtime chip id）指定另一个控制端口去触发复位，复位完成后再回到日志端口继续接收。
复位 ≠ 断开 复位只改变 DTR/RTS 电平让设备重启，不会断开当前串口连接；复位后设备重新打印的内容会继续出现在日志视图里。

4. 日志视图

日志视图是页面的主体，实时滚动显示收到的数据。它支持两种视图与一组显示开关：

  • ASCII 视图 与 Hex 视图：可在普通文本和十六进制之间切换；Hex 视图可设置每行字节数（8 / 16 / 32），并把不可见字节以十六进制明文展示。
  • ANSI 着色开关：解析日志中的 ANSI 颜色转义码并上色，便于区分不同等级的日志。
  • 字号：10–18px 范围内调节，适应不同屏幕和阅读习惯。
  • 时间戳开关：在每行前显示接收时间。
  • 方向徽标开关：在每行前标注 TX（发送）/ RX（接收）/ SYS（系统消息）方向。
  • 清空（clear）：清掉当前可见缓冲区。
  • 导出（export）：把当前日志导出为文件。
可见窗口上限 3000 行 为保证性能，可见窗口最多保留 3000 行；超出后旧行会被从视口移除。需要完整会话记录时请使用下方自动保存，或在数据丢失前及时导出。

5. 发送栏

底部的发送栏用于向设备主动发送数据：

  • ASCII 或 Hex 模式：ASCII 模式按文本发送；Hex 模式按十六进制字节发送（用于发送二进制指令）。
  • 可选 \r\n：发送时是否在末尾追加回车换行，按目标设备的协议勾选。
  • 回车发送：按 Enter 即发送当前输入框内容。
  • 发送历史：最多保留 20 条历史；用 ↑ / ↓ 在历史条目之间快速翻选，无需重复输入。

6. Hex 弹窗

在日志视图中选中一段 RX 数据后，可以打开一个 Hex 弹窗，把所选字节同时以十六进制和 ASCII 两种形式并排展示，方便逐字节核对一段二进制回复或协议帧。

什么时候用 当设备返回的是结构化二进制（例如自定义协议帧、授权回复）而不是可读文本时，用 Hex 弹窗逐字节检查比在 ASCII 视图里看乱码要可靠得多。

7. 过滤标签（Watch chips）

过滤标签（watch chips）让你给感兴趣的关键词各建一个标签，从而在一长串日志里只看相关内容：

  • 关键词：可以是纯文本，也可以是正则表达式。
  • 自动配色：每个标签自动从 6 色循环里取一个颜色，便于一眼区分。
  • 实时计数：每个标签上显示当前会话内命中的条数，随日志增长实时更新。
  • 按标签过滤：点选某个标签后，视图只显示匹配该关键词的行；“全部（All）”标签则恢复显示全部内容。
  • “加载更早（load older）”：匹配结果较多时分页加载更早的命中行。

过滤是在服务端、针对整个会话执行的，而不是只过滤当前可见窗口——因此即便旧数据已经从 3000 行视口里被移除，过滤结果仍能把它找回来。

8. 自动释放 / 自动保存

这两项功能都在设置里配置，用来让长时间挂着的串口调试会话更省心。

自动释放（Auto-release）

自动释放解决的是端口争用问题：

  • 当固件烧录页需要使用某个端口、而该端口正被串口调试占用时，串口调试会自动释放该端口交给烧录使用；可以开启确认提示，在释放前先问你一句。
  • 烧录结束后，串口调试会自动恢复之前的连接，继续接收日志，无需你手动重连。

自动保存（Auto-save）

自动保存用于留一份完整的会话日志，避免超过 3000 行视口上限后丢数据：

  • 保存目录：选一个目录，串口调试会把整段会话流式写入其中。
  • 时间戳文件名：可选在文件名里加上时间戳，便于区分不同会话。
  • 分块写入：以最大 128 KiB 的块落盘，兼顾写入效率与及时性。
自动保存 vs 手动导出 手动导出（见日志视图）保存的是当前可见窗口内的内容；自动保存则是把整个会话持续落盘，是留存长时间日志的正确做法。
