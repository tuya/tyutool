批量授权 · 固件开发者必读

本页写给固件开发者：要让你的固件能被 tyutool 批量授权，固件必须实现一套 TuyaOpen UART CLI 命令。下面给出完整协议契约与自测清单——自测通过即代表固件已具备批量授权能力。

走错页了？ 如果你是使用软件进行烧录授权的操作员（只想知道怎么点按钮、出问题怎么办），请看 批量授权 · 操作员指南，那里没有协议细节。

1. 协议本质：文本 CLI，不是二进制帧

tyutool 的授权协议是TuyaOpen 交互式 shell 的文本命令——纯 ASCII、每条命令以 \r\n 结尾、没有帧头/校验和/操作码。这和烧录固件用的 Beken BootROM 二进制协议是两套完全独立的东西。授权阶段对话的对象是设备启动后运行的那个 CLI shell。

  • 波特率：默认 115200 8N1（可被批量配置的“授权波特率”覆盖）。
  • 交互方式：设备上电后呈现 tuya> 提示符；tyutool 逐条发送命令，读取回显判定结果。
  • 权威来源：TuyaOpen 的 tuya_authorize.c——最省事的做法就是基于 TuyaOpen 开发，它已实现本页全部命令。
最快上手 你的固件若基于 TuyaOpen 构建，授权 CLI 已自带，无需自己实现。本页主要面向自研或移植固件、需要自行实现这套 CLI 的开发者。

2. 固件必须实现的命令

下表是 tyutool 在授权流程中会发送的全部命令，以及固件必须回显的内容。命令名大小写敏感（小写），<uuid>/<authkey> 为实际凭据，<n> 是存储模式参数（见 第 4 节）。

命令（\r\n 结尾）用途固件必须回显的内容
sys_log_enable off 能力探测 + 关闭日志 新固件：OK: log disabled；旧固件：No command 或直接回到 tuya> 提示符
sys_version 读取固件版本 一行形如 project.version x.y.z
read_mac 读取设备 MAC 形如 XX:XX:XX:XX:XX:FF（6 段冒号分隔的十六进制；也可带前缀标签 LABEL:XX:...:FF 共 7 段）
auth-read
或 auth-read <n>		 读取当前授权（UUID + AuthKey） 已授权：连续两行 <uuid> 与 <authkey>，随后提示符；
空/未授权：Authorization read failure.
auth <uuid> <authkey>
或 auth <uuid> <authkey> <n>		 写入授权 长度非法：uuid length must be 20/16, authkey length must be 32（且不执行写入）；
OTP 写入成功：Authorization write to OTP Succeeds.；
OTP 写入失败：Authorization write to OTP failure.
关于回显约定 固件应回显（echo）每条收到的命令行——tyutool 会过滤掉自身发出的命令回声，只看后续的真实输出。日志行（形如 [MM-DD HH:MM:SS ...]）和 ANSI 转义会被自动剔除，不必为它们特殊处理。

3. 凭据长度规则

固件在执行 auth 写入前会先校验长度；tyutool 在 Excel 录入阶段也会用同样的规则预先剔除不合法的行（这些行永不烧录）：

字段合法长度非法时
UUID恰好 16 或 20 字符固件回显长度错误，tyutool 直接报失败
AuthKey恰好 32 字符同上
  • 未授权设备的占位 UUID 为 uuidxxxxxxxxxxxxxxxx。
  • UUID 合法字符：字母数字及 - _ .；AuthKey 合法字符：任意 ASCII 可见字符。

4. KV 与 OTP 的协议差异

存储模式只通过命令末尾追加一个数字参数 <n> 来区分，KV 省略、OTP 追加 1：

模式读命令写命令
KV（键值区，可重写）auth-readauth <uuid> <authkey>
OTP（一次性 eFuse，写一次不可逆）auth-read 1auth <uuid> <authkey> 1
  • OTP 仅 T5AI 暴露；其他芯片一律走 KV。
  • OTP 烧写耗时长：命令回声与响应之间有较长静默期（eFuse 烧写）。tyutool 对 OTP 写入用 60 秒总超时 + 30 秒静默窗口，OTP 读取用 30 秒静默窗口。
  • OTP 写失败会重试：失败时 OTP 区块仍为空（写一次语义：区块非空才拒绝再写），因此最多重试 3 次不会损坏已写数据。
  • OTP 读取空区会回显 Authorization read failure.，tyutool 视为“未授权”而非错误。
OTP 写一次不可逆 一旦 OTP 区块写入非空，固件将拒绝任何再次写入，且无法擦除/修改。开发调试阶段务必先用 KV 模式完整验证流程，确认无误后再切 OTP。

5. MAC 校验规则

  • read_mac 回显的 MAC 必须是有效的设备 MAC。
  • T5/T5AI 出厂默认 MAC C8:47:8C:00:00:18 表示设备 MAC 区尚未个性化——读到它 tyutool 会中止该设备授权。固件侧应保证读出来的是个性化后的真实 MAC。

6. 自测清单（测试通过即可投入批量）

你强调的核心：固件开发过程中，需要自己通过串口手工输入命令测试通过，才能用批量功能。用任意串口工具（minicom / picocom / 串口调试助手），115200 8N1 连上设备，按顺序逐条发送并核对回显。全部勾选通过，即代表固件已具备批量授权能力：

  1. ☐ 设备上电后出现 tuya> 提示符（连发两个空 \r\n 能唤醒 shell）。
  2. ☐ 发送 sys_log_enable off，收到 OK: log disabled（或旧固件的 No command / 回到提示符）。
  3. ☐ 发送 sys_version，收到一行 project.version x.y.z。
  4. ☐ 发送 read_mac，收到有效的 XX:XX:XX:XX:XX:FF（且不是 C8:47:8C:00:00:18）。
  5. ☐ 发送 auth-read，在未授权设备上收到 Authorization read failure.。
  6. ☐ 发送 auth <一组合法 uuid+authkey>（UUID 16 或 20 字符、AuthKey 32 字符），写入后再次 auth-read 能读回相同的 UUID 与 AuthKey。
  7. ☐ 发送 auth <过短的uuid> <key>，收到 uuid length must be 20/16, authkey length must be 32 且不改变已有授权。
  8. ☐（仅 T5AI + OTP 路径）发送 auth <uuid> <authkey> 1，收到 Authorization write to OTP Succeeds.；再发 auth-read 1 能读回。
自测用凭据从哪来 自测请用合法购得的真实凭据。若只想验证协议握手，可在 KV 模式下重复擦写同一组；OTP 模式因写一次不可逆，建议最后再验。

7. 两条集成路径

  • 路径 A（推荐）：固件自带授权能力——基于 TuyaOpen 开发（或自行实现上述 CLI），生产固件本身就能响应授权命令。批量时用 auth-only 模式，tyutool 直接和你固件里的 shell 对话。
  • 路径 B：用官方 auth-firmware 临时烧入——若你的生产固件不实现这套 CLI，可在批量时先烧入 tyutool 提供的 auth-firmware（assets/auth-firmware/ 下按芯片提供 .bin），用它完成授权，再由后续产线环节刷入你的生产固件。对应批量 flash-then-auth 模式。注意：auth-firmware 本身就是一份实现了本契约的 TuyaOpen 固件。

8. 交付批量生产前：给操作员的配置交接单

固件自测通过后，别只丢一个 bin 给产线。请把下面每一项逐项写清楚交给操作员——操作员会按操作员页的配置交接单逐行核对，缺一项就可能配错整批：

  • 芯片型号（如 esp32 / t5ai；只授权不烧录写 other）。
  • 操作模式：路径 A（auth-only，生产固件自带授权 CLI）还是路径 B（flash-then-auth，先烧 auth-firmware）——对应操作员界面的"烧录固件"开关。
  • 固件文件名 + 版本；路径 B 注明用官方 auth-firmware 的哪个版本。
  • 两个波特率：烧录波特率（按芯片推荐值）和授权波特率（= 固件 shell 波特率，通常 115200）。
  • 存储模式：KV 还是 OTP。选 OTP 必须显著标注，并注明"先单台验证再批量"。
  • 冲突策略：跳过还是覆盖（OTP 只能跳过）。
  • 接线说明：烧录/授权口的位置（T5/T5AI 切勿接日志口），最好配一张接线照片。
  • MAC 唯一性保障：说明每台设备的 MAC 在哪个环节个性化、如何保证全球唯一、互不重复。tyutool 不校验 MAC 是否与其他设备冲突，而授权码与 MAC 绑定——重复的 MAC 会让不同设备共用同一个授权码，设备在涂鸦平台将无法正常识别。这是操作员无法自行验证的项，必须由固件/产线侧保证。
  • 特殊事项：默认 MAC 未个性化设备的处理、供电要求、已知的坑。
为什么值得花这五分钟 批量授权的错误配置成本极高（OTP 配错 = 整批报废）。交接单让操作员"照单执行"而不是"凭经验猜"，也让事后排查时能对着批次档案还原当时的约定。
