# 串口调试可靠性修复

**Plan:** `docs/plans/2026-10-19-serial-debug-reliability.md`

## 问题与基线

分支 `codex/log-latency` 已修复持续小包输入的批量推送延迟。后续 review 的回归测试现已落盘：新增 10 项，9 项因已确认的问题失败，1 项关闭排空契约通过。现有测试仍通过。

## 决策

1. 自动保存跟随串口会话而非可见页面，切页继续定期写盘；清空与切换保存目录必须先处理旧文件的待写内容，错误必须可见，不静默丢弃。
2. 关闭按停止串口、确认后端推送排空、处理前端最后一批与尾行、解除监听的顺序执行。Tauri 与 Web 保持相同数据契约；补桌面宿主的关闭路径行为测试。
3. 数据丢失的位置必须与接收流保持顺序。提示可以聚合，但不能把缺口两侧内容拼成一行；串口读取线程仍须非阻塞。
4. 十六进制视图保留已有原始字节，不插入分隔字节。历史归档继续保持文本格式，不宣称可恢复任意二进制原文。
5. 清空后的筛选请求失效；导出固定开始时的筛选和数据上限，不受切页或持续新数据影响。
6. 缓存维护只在有证据且能保持简单实现的情况下优化，用结果一致性、缓存边界与操作量验证，不设机器耗时门槛。

## 本轮边界

修复已确认的八类缺陷并完成对应测试。不改变归档格式、归档容量与凭据隔离规则，不新增实时尾行预览、设置项或第三方依赖。未完成行实时预览属于独立交互增强，保留现有组行契约。

## 执行与审查

由三个 Luna 子 agent 分别执行后端、会话与保存、显示与导出任务。主 agent 负责计划、文件边界协调、差异审查、交叉场景验证和最终门禁；禁止通过跳过测试或放宽正确性断言完成任务。

## 二次修复决策

1. 自动保存单独记录当前文件所属的保存根目录，以精确比较处理目录变更；文件名保留可读时间戳，并增加 UUID 区分每次保存会话，不改变通用时间戳工具。
2. Tauri 清空、打开、关闭使用同一生命周期 reservation。冲突时返回错误，既不推进代际也不清归档；前端保留日志并显示错误，用户可在关闭完成后重试清空。
3. 导出捕获本地归档修订号。清空进入和退出都使先前导出失效，异步对话框、读页和写入边界均检查修订号；失效时提示取消。桌面上已写入的旧归档部分可以保留，但不能继续追加新归档内容。本轮不新增跨后端快照协议，也不承诺原子文件替换。
4. 后端清空成功后再重置前端日志；等待期间已到达的原始块和尾部仍进入自动保存队列，旧归档的回填水位与筛选请求不能跨越重建边界。
